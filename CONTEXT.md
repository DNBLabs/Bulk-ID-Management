# Context: Bulk Identity Management

Glossary and domain language for this repository. Implementation details belong in code and ADRs, not here.

| Term | Definition |
|------|------------|
| **Entra tenant** | The Microsoft Entra ID directory where users and groups are created. |
| **Automation principal** | The non-human identity used by scripts and CI to call Microsoft Graph. Implemented as an **App registration** (service principal), not an interactive user session. |
| **CI credential** | How the pipeline authenticates as the automation principal. This project uses **federated workload identity (OIDC)** from GitHub Actions to Azure AD—no long-lived client secret in the repository for CI. |
| **Bulk provisioning** | Creating many directory users from structured input (here: CSV rows) with consistent rules. |
| **CI scope** | Continuous integration for this repo runs **validate-only** work (e.g. static analysis, tests, syntax checks). It does **not** create or modify Entra objects on every PR or push. |
| **CI validation gates** | Default pipelines run **PSScriptAnalyzer** against repository **`.ps1`** / **`.psm1`** code and **fail** on **Error** and **Warning** severities. They also run **Pester** tests over **deterministic** logic (e.g. **Provisioning CSV format** checks, **IT department rule** matching, **Identity derivation** / nickname normalization edge cases). **Microsoft Graph** is **not** called in these default workflows. |
| **Apply** | The act of creating or changing Entra users/groups using the automation scripts (as opposed to CI validation). |
| **Dry run** | An apply mode (e.g. **`-WhatIf`** / **`-DryRun`**, following PowerShell naming) that performs **read-only** resolution where needed and prints an explicit **plan** (per row: create user, skip, ensure group membership, etc.) but **does not** create users, **does not** set or rotate passwords, and **does not** add group members. Documentation instructs operators to **dry-run before mutating apply**. |
| **Apply path** | **Primary:** run scripts **locally** (or on a self-hosted runner you control) with documented authentication. **Optional:** a **separate** GitHub Actions workflow triggered only by **`workflow_dispatch`** (manual), clearly labeled as tenant-mutating—not part of default PR checks. If that workflow exists, it targets a **GitHub Environment** (e.g. **`entra-apply`**) with **required reviewers** so tenant-mutating jobs cannot proceed without explicit approval. |
| **Local apply authentication** | Connect to Microsoft Graph **as the automation principal** using **certificate-based client credentials** (private key and cert **outside the repository**; script parameters or config reference thumbprint, cert path, **tenant ID**, and **client ID**). **Client secret** is **not** the default documented path. A **second** documented mode (e.g. delegated device code) is **out of scope for v1** unless explicitly added later—avoid mixing permission models with the chosen **application** permissions. |
| **Provisioning row** | One CSV row representing one person to provision. After CSV validation, each row is materialized with **FirstName**, **LastName**, and **Department** always present. Optional CSV columns **MailNickname**, **UserPrincipalName**, **GivenName**, **Surname**, and **DisplayName** are exposed on the row **only when** that exact column name appears in the header row and the cell is non-empty after trim—a minimal three-column file does not add empty placeholder properties for optionals. All materialized string values are **trimmed** (leading/trailing whitespace removed) at the CSV boundary. Each row includes **`SourceLineNumber`**: the **1-based physical line number** in the source file (same numbering as validation errors). Identity fields not supplied in CSV are derived later (**Name mapping**, **Identity derivation**). The **Department** value is persisted on the user as the Entra **`department`** attribute, not used only for group logic. |
| **Mapped provisioning identity** | The result of **Name mapping** and default **MailNickname** normalization for one **provisioning row**. Exposed by **`Get-MappedProvisioningIdentity -ProvisioningRow`** as a **new** object (input row is not mutated): **`SourceLineNumber`**, **`GivenName`**, **`Surname`**, **`DisplayName`**, **`MailNickname`** (PascalCase property names). **`UserPrincipalName`** on the row is **not** set here—**Identity derivation** (Task 5) reads the row and mapped nickname. Invalid normalized **MailNickname** causes **`Get-MappedProvisioningIdentity`** to **throw** a **terminating** **`System.InvalidOperationException`** whose message cites **`SourceLineNumber`** (physical file line); the orchestrator catches per row and records **row outcome** **failed** without stopping the batch. |
| **Name mapping** | Default: **`givenName`** from **FirstName**, **`surname`** from **LastName**, **`displayName`** from **FirstName**, a single space, and **LastName**—each component **trimmed** and **internal runs of whitespace collapsed to a single space** before use. **Diacritics and non-ASCII letters are preserved** in **`GivenName`**, **`Surname`**, and **`DisplayName`** (e.g. **José**, **García**, **Renée**); only **MailNickname** normalization strips accents for ASCII-safe aliases. When the row includes non-empty **GivenName**, **Surname**, or **DisplayName** (header present and cell non-empty after CSV trim), that value **overrides** the corresponding default, with the same trim/collapse applied. Example: **FirstName** `Robert` with **GivenName** `Bob` yields **`GivenName`** `Bob`, not `Robert`. The **v1** committed sample CSV stays minimal (core columns only); override columns are optional in data files. |
| **Identity derivation** | **UserPrincipalName** may be supplied in full on the row, or built from **MailNickname** (or derived nickname) plus a **tenant domain suffix** supplied via script/config (verified domain), never committed as a secret. Default **MailNickname** base (when CSV **MailNickname** is absent): **mapped** **`GivenName`** and **`Surname`** from **Name mapping** (after optional CSV overrides—not raw **FirstName** / **LastName** unless no override), each **trimmed** and **internal whitespace collapsed to a single space**, joined with a **literal dot** (`.`); then **normalized** (lowercase; **Unicode Form D** decomposition with non-spacing marks removed for accents; **`ß` explicitly mapped to `ss`**; **remove all spaces**; then keep only characters in **`[a-z0-9.-]`**—letters, digits, dot, hyphen; **apostrophes and other punctuation are removed**). Example: **Anne** + **O'Brien** → **`anne.obrien`**. Example: **Jean-Luc** + **Picard** → **`jean-luc.picard`**. Example: **José** + **García** → **`jose.garcia`**. Example: **Mary Jane** + **Watson** → **`maryjane.watson`**. **displayName** and other **Name mapping** fields are unchanged (spaces allowed there). Optional CSV **MailNickname** / **UserPrincipalName** columns **override** defaults when present on the row. When **MailNickname** is supplied in CSV, the **same normalization pipeline** runs as for a derived nickname (lowercase, strip accents, remove spaces, safe characters)—operators choose the alias in data; the tool does not pass through raw casing or diacritics. After charset filtering, **collapse runs of `.` and `-`**, **trim** leading/trailing `.` and `-`, then **validate**: the nickname must be non-empty and contain **at least one letter** (`a-z`); otherwise that **provisioning row** **fails** with a clear error citing **`SourceLineNumber`** (orchestrator records a **row outcome** of **failed** on **apply**; other rows continue per **batch error policy**). **Collision handling:** if the nickname or UPN is taken, append a numeric suffix after checking Microsoft Graph. |
| **Re-run behavior** | On **apply**, if a row’s **UserPrincipalName** already exists: **default** is **skip** user creation for that row (idempotent, no silent attribute drift). An explicit opt-in (e.g. **`-UpdateExisting`**) may **update only a documented subset** of attributes: **`department`** (from CSV **Department**), **`givenName`**, **`surname`**, **`displayName`** per **Name mapping**—and no other fields unless later documented. **Strict fail-fast** on conflict is **not** the default. |
| **IT membership group** | The **assigned** Entra security group that receives users whose **Department** matches the IT rule. The group is **pre-created** by an administrator; the automation does **not** create this group in the first version. The script resolves the group by a **stable identifier** supplied at apply time—prefer **group Object ID**; alternatives may include the group’s **mailNickname** if documented. **Fuzzy display-name search alone** is not the canonical resolution method. |
| **IT department rule** | A row qualifies when its **Department** value equals a configured target (default **`IT`**) under a **case-insensitive** comparison. |
| **Initial password** | For each **new** user, a **cryptographically random** password that satisfies tenant policy, with **`forceChangePasswordNextSignIn`** enabled. Password material is surfaced only through **secure, non-persistent** means (e.g. in-session handling); it is **not** written to repo files, default logs, or CI artifacts. Documentation warns that **apply** output may be sensitive. |
| **Usage location** | ISO 3166 alpha-2 country/region code on the user (e.g. **`US`**). In **v1**, an **optional apply-time parameter** sets **usageLocation** for **each newly created user** when provided; when omitted, the script does not set the field. A **future** optional CSV column may **override** per row without changing the default small sample file shape. |
| **Graph application permissions** | **Application** (not delegated) permissions on the automation principal, with **admin consent**, kept to least privilege for this scope: **`User.ReadWrite.All`**, **`Group.Read.All`**, **`GroupMember.ReadWrite.All`**. **`Directory.ReadWrite.All`** is **out of scope** as a default. |
| **IT membership ensure** | On **apply**, for each row matching the **IT department rule**, after the directory user is resolved (**created** or **already present**), the automation **idempotently ensures** membership in the **IT membership group** (add if missing; **no-op** if already a member). This runs even when **user creation** was **skipped** under **Re-run behavior**. **Removing** users from that group when a row is non-IT or **Department** changes is **out of scope for v1**. |
| **Row outcome** | The result of processing one **Provisioning row**: e.g. created, skipped (existing UPN), updated (when opted in), membership ensured, or failed—with a **human-readable reason** for failures. |
| **Batch error policy** | On **apply**, if one row fails, processing **continues** for remaining rows. The run emits an **aggregate report** of **row outcomes**. The process exits with **non-zero** if **any** row failed. A future **`-StopOnFirstError`** (or equivalent) may be added; it is **not** the v1 default. |
| **Account state (new users)** | Users **created** by this automation are **`accountEnabled = true`** by default so they can sign in after password reset / first sign-in. A **staged** (create-disabled) mode is **out of scope for v1** unless added later as an explicit opt-in flag. |
| **License assignment** | **Out of scope for v1.** This automation creates/updates users and manages **security group membership**; it does **not** assign Microsoft 365 or other product **licenses**. Follow-up may use separate automation (e.g. Graph **`assignLicense`**) or tenant policies such as **group-based licensing**. |
| **Graph API version** | All Microsoft Graph requests in **v1** of this project use the **`v1.0`** endpoint surface only—not **`beta`**—unless a future release documents a deliberate exception. |
| **Provisioning CSV format** | Input files are **comma-separated** (**`,`**) with **comma** (**`,`**) as the only field delimiter—**no** semicolon or other delimiter auto-detection—and **RFC-style** field quoting (double-quoted fields, commas inside quotes, escaped quotes), encoded **UTF-8** only; a **UTF-8 BOM** at the start is **allowed** and must be handled when reading. Files that are not valid **UTF-8** (invalid byte sequences) **fail import** with a clear encoding error—no fallback decoding and no rows emitted. The **first row** is a **header** row. Header cell names are compared **case-sensitively** to the canonical spellings (**FirstName**, **LastName**, **Department**, and documented optional names) after **trimming leading/trailing whitespace** on each header cell—`firstname` or `FIRSTNAME` does **not** satisfy **FirstName**. The file must include all required column names. If required headers are missing, headers are duplicated after trim, or the file is not parseable as this contract, validation **fails with a clear error** before any **Apply** Graph calls. **Required** data cells (**FirstName**, **LastName**, **Department**) must be non-empty after trimming leading/trailing whitespace; otherwise validation **fails the entire import** with an actionable message including **row number** as the **1-based physical line number in the file** (header = line **1**; first data row = line **2**), so operators can match Excel and editor line numbers (no rows are emitted for downstream processing). If an **optional** column appears in the header but a row’s cell is blank or whitespace-only, that is **not** an override—the row omits that optional property and downstream derivation applies. A **data row** whose cells are all empty or whitespace-only after trim is **skipped** (no **provisioning row** emitted). If every data row is skipped, validation **fails** (“no provisioning rows”). **Unknown** header columns (names not in the v1 contract) are **ignored**—values under those columns are not read and do not appear on **provisioning row** objects. |
| **User type (v1)** | Rows represent **workforce (member)** directory users. The automation does **not** invite **Guest** (B2B) users or combine member and guest flows in one CSV for **v1**. **Guest invitation** and B2B redemption flows are **out of scope** unless added later as a separate documented mode. |
| **Graph transient policy** | On **429** (throttling) or selected **5xx** responses from Microsoft Graph during **apply**, the client performs **bounded retries** with **exponential backoff** and honors **`Retry-After`** when the service supplies it. Retries are **capped** (max attempts and/or max cumulative wait per logical operation). If limits are exceeded, the affected **Provisioning row** is marked **failed** per **Batch error policy**—no unbounded retry loops. |
| **PowerShell baseline** | Scripts and CI assume **PowerShell 7** (`pwsh`), minimum **7.2** (LTS line) with **7.4+** preferred as the documented baseline. **Windows PowerShell 5.1** is **not** a supported target for v1. Validation workflows invoke **`pwsh`** (e.g. on Linux or Windows runners). |
| **Module version manifest** | **Microsoft.Graph** (and related) PowerShell modules use **pinned exact versions** recorded in a **repository-owned file** (for example **`RequiredModules`** in a module manifest or a dedicated **`requirements.psd1`**). CI and documented local setup **install from that manifest**—not an implicit **latest** from the gallery. Bumping Graph module versions is an **intentional, reviewable change** (typically its own small PR). |
| **Apply output hygiene** | By default, **apply** console / transcript output avoids **personal data** where practical: no **passwords**; avoid **full UPN**, **object IDs**, and similar identifiers in default streams. Output is **operational** (e.g. row index, action, **Row outcome**). An explicit opt-in (e.g. **`-ShowIdentifiers`**, off by default) may print fuller identifiers for **lab debugging** only, with README warning. |
| **Documentation authority** | **`CONTEXT.md`** is the **normative** glossary and behavioral contract for this repository. **`docs/init-project.txt`** is an **informal brief** (e.g. learning assignment); if they conflict, **CONTEXT** prevails. The **README** should direct readers to **CONTEXT.md** first and may cite **`init-project.txt`** only as background or motivation. |
